# Searchbox 规划

日期：2026-10-20
状态：M0 已验证，M1 未开始

---

## 1. 定位

把 JSON 搜索 API 变成浏览器里的搜索结果页：**插件是解释器，搜索源是可配置数据**。

- 目标用户：作者本人（自用），不发布到扩展商店。
- 不做：分页/翻页、HTML 抓取、OAuth 或签名鉴权、云端同步、结果缓存、账号体系、地址栏默认引擎接管（见 §2.1）。

相似产品的位置（调研结论）：BigSearch 一系能声明式配置引擎但只拼 URL 跳站、不解析响应；SearXNG 生态有自己的结果页与配置化引擎但需要服务器、且抓 HTML；AI 搜索扩展有结果页但源锁死。三者交集为空。

## 2. 硬约束（实测）

### 2.1 扩展页不能当搜索引擎

A/B 对照实验（Edge 155.0.4283.62，独立 profile，同一把密钥，仅改 `search_url` 协议）：

| 组 | `search_url` | 结果 |
|---|---|---|
| A | `chrome-extension://<id>/probe.html?q={searchTerms}` | 扩展加载失败 |
| B | `https://example.com/?q={searchTerms}` | 扩展加载成功 |

A 组安装日志原文：

```
Extension error: 无法从以下源加载扩展: ...\m0-probe.
Invalid URL [chrome-extension://ehmpekhplannbpehinceahghighiaifi/probe.html?q={searchTerms}]
for 'chrome_settings_overrides.search_provider'.
```

结论：`chrome_settings_overrides.search_provider.search_url` 只接受 http(s)。接管地址栏必须有一个 http(s) 页面（本地服务或线上服务）。**本规划不做地址栏接管。**

佐证：Edge 内置引擎存在 `edge://favorites/?q={searchTerms}`、`edge://history/all?q={searchTerms}` 这类非 http 协议，说明 scheme 校验只作用于扩展提供的引擎。

### 2.2 其他已验证约束

| 约束 | 内容 |
|---|---|
| 新标签页覆盖 | `chrome_url_overrides` 只能在 manifest 静态声明，运行时不可开关 |
| 主机权限 | MV3 `host_permissions` 静态；运行时新增来源需 `optional_host_permissions: ["https://*/*"]` + **用户手势内** `permissions.request()` |
| 引擎图标 | `search_provider.favicon_url` 必须是绝对 URL；相对路径报 `Invalid URL [icon.png]` |
| 站点图标 | 用内置接口 `chrome-extension://<id>/_favicon/?pageUrl=<url>&size=32`，需 `favicon` 权限 + `web_accessible_resources` 放行 `_favicon/*` |
| anysearch 匿名 | `POST https://api.anysearch.com/v1/search`，body `{"query":"...","max_results":N}`，返回 `{code,message,request_id,data:{results:[{title,url,snippet,content}]}}`，key 走 `Authorization: Bearer <key>` 可选 |
| anysearch 参数类型 | `max_results` 必须是数字。传字符串返回 400：`json: cannot unmarshal string into Go struct field SearchRequest.max_results of type int`。因此模板里"整串是一个占位符"时必须保留原始类型，不能一律转字符串 |
| 站点图标来源 | `_favicon` 只返回浏览器**已缓存**的图标；未访问过的站点返回占位图（实测：访问前 211 字节，访问后 1873 字节）。搜索结果里首次出现的站点会显示占位图标，属正常行为 |
| CDP 导航限制 | 无法用 DevTools 协议把标签页导航到 `chrome-extension://` 页面（返回 `ERR_BLOCKED_BY_CLIENT`）；验证扩展页面须由扩展自身 `chrome.tabs.create` 打开 |
| 权限申请的时机 | `chrome.permissions.request()` 必须在用户手势内**同步**发起；一旦前面有任何 `await`，手势失效、调用会抛错。设置页保存时把这个调用放在所有 await 之前 |
| contextMenus.create | Edge/Chrome 的 `chrome.contextMenus.create` **不返回 Promise**，重复创建只在 `chrome.runtime.lastError` 里报错；必须用回调式并显式读取 lastError，否则错误处理是假的 |
| 跨标签页写 storage | `get` + `set` 的读-改-写**不是原子的**：实测两个搜索页同时记录历史会丢一条。需要多上下文并发写的结构应改成「一实体一个键」，用单键写入回避竞态 |
| 私钥位置 | 生成扩展 ID 用的私钥若放在扩展目录内，浏览器加载时会告警「此扩展包括密钥文件」。私钥存放于仓库外 `D:\GXD\0\.keys\searchbox_key.pem`；日常开发不需要它，只有打包 .crx 时才用得上 |
| Tavily | `POST https://api.tavily.com/search`，鉴权走 `Authorization: Bearer <key>`（官方 quickstart 写法），body 含 `query` / `max_results` / `search_depth` / `chunks_per_source`，返回 `{results:[{title,url,content,...}]}` |

## 3. 架构

### 3.1 文件树

扩展本体放在 `searchbox/` 子目录，与仓库其余内容（git 元数据、决策记录）分离：
浏览器会扫描整个被加载目录，混放会触发不必要的告警。

```
searchbox/manifest.json # MV3：storage / favicon / contextMenus / tabs + host_permissions
searchbox/src/
  search.html          # 唯一页面：无 q = 首页，有 q = 结果页
  search.js            # 读参数、渲染、键盘交互
  search.css           # 含深色模式
  options.html         # 配置编辑器 + 测试面板 + key
  options.js
  bg.js                # 右键菜单注册 + 新标签页软接管
  core/
    preset.js          # 内置源定义
    request.js         # 占位符替换 + fetch + 超时/取消
    extract.js         # okPath / itemsPath / fields 解析
    merge.js           # URL 归一化 + 去重 + 名次交错
  tests.html           # 纯函数断言页
assets/icon-*.png
```

### 3.2 数据流

```
新标签页 → search.html（空态）
  输入 → search.html?q=...
  → core/request.js：按配置并发请求所有 enabled 源
  → core/extract.js：按配置取出 {title, url, snippet}
  → core/merge.js：URL 归一化 → 去重 → 名次交错
  → 渲染（图标走 _favicon 接口）
```

### 3.3 配置 schema

```jsonc
{
  "id": "anysearch",
  "name": "AnySearch",
  "origin": "https://api.anysearch.com",     // 权限申请用
  "enabled": true,
  "request": {
    "url": "https://api.anysearch.com/v1/search",
    "method": "POST",
    "headers": { "Authorization": "Bearer {{key}}" },  // key 为空 → 整条省略（走匿名）
    "body": { "query": "{{query}}", "max_results": "{{limit}}" }
  },
  "response": {
    "okPath": "code", "okValue": 0,          // 无外层包装的源不填
    "errorPath": "message",
    "itemsPath": "data.results",
    "fields": {
      "title": ["title"],
      "url": ["url"],
      "snippet": ["snippet", "content"]      // 依次兜底
    },
    "captureKeyPath": "data.auto_registered.api_key"   // 可选：响应里回传新 key
  },
  "limits": { "timeoutMs": 10000 }
}
```

```jsonc
{
  "id": "tavily", "name": "Tavily", "origin": "https://api.tavily.com", "enabled": false,
  "request": { "url": "https://api.tavily.com/search", "method": "POST",
               "body": { "api_key": "{{key}}", "query": "{{query}}", "max_results": "{{limit}}" } },
  "response": { "itemsPath": "results",
                "fields": { "title": ["title"], "url": ["url"], "snippet": ["content"] } }
}
```

占位符只有三个：`{{query}}`、`{{key}}`、`{{limit}}`。**含未解析占位符的 header/body 字段整条省略**，不写空值。配置语言不引入条件、循环、表达式；无法表达的源一律不支持。

## 4. 已定决策

| 编号 | 决策 | 理由 |
|---|---|---|
| D1 | 新标签页用**软接管**：`tabs.onCreated` 检测新标签页 → `tabs.update` 跳到扩展页 | `chrome_url_overrides` 无法运行时开关；软接管可以做成设置项。代价：短暂闪烁 + 需要 `tabs` 权限 |
| D2 | 结果**名次交错**：各源第 1 条等权、第 2 条等权，同分按源优先级；每条带源标签 | 各家 score 无共同尺度，按分数混排等于伪造排序 |
| D3 | 请求在**页面内直连**，不经 service worker 转发 | 入口只有搜索页与设置页测试面板，两者都能 import 同一模块；避免 MV3 后台生命周期问题。入口增至三个以上再迁后台 |
| D4 | 内置源作为 preset，与 storage 中用户版本按 `id` 合并，用户版本覆盖 | 扩展升级能更新内置源，又不覆盖用户改动。内置源可禁用/重置，不可删除 |
| D5 | 纯函数用 `tests.html` 断言页回归（本机无 node 运行时） | 覆盖占位符替换、路径提取、URL 归一化去重、名次交错；零依赖、一键全绿 |
| D6 | 配置界面是 JSON 编辑器 + 校验 + 测试面板（原始响应与解析结果并排） | schema 会演进，表单要跟着改；测试面板同时是新源接入的调试入口 |
| D7 | 单源视图展示该源**原始返回**，不参与跨源去重；只有「全部」视图做合并去重 | 点某一家时用户要看的是"这家返回了什么"，条数应与标签上的数字一致；跨源去重是合并视图的事 |
| D8 | 渐进式渲染：任一源返回就立刻重算并重绘，未返回的源显示「搜索中…」 | 等最慢的源会让快的源白等着；用户先看到东西比看到完整列表更重要。重绘时保留滚动位置 |
| D9 | 标题本身是裸 URL 时显示域名 | 有些接口把 title 直接填成链接，展示一串 URL 不可读 |
| D10 | 跨源重复命中时保留一条、把其余来源记在 `sources` 上并全部展示 | 用户需要知道“这条不只一家收录”，但不能为同一链接刷出多个条目 |
| D11 | 历史 30 天过期 + 上限 50 条，清理在读取时进行 | 只增不减的本地数据没有意义；放在读取路径上不增加写入成本，也不引入并发写风险 |
| D12 | 「每个来源取多少条」做成设置项（1–50，默认 10）；「合并后总上限 40」不开放 | 前者是用户的网速/耐心权衡，后者决定产品形状（列表长度、翻页缺失），开放出去只会产生坏配置 |
| D13 | 新标签页接管改为「扩展新建同位标签 + 删除旧标签」，而不是 `tabs.update` 原地跳转 | 实测：浏览器自己创建的标签焦点在地址栏，扩展 `tabs.create` 出来的标签焦点在页面。原地跳转会让人 Ctrl+T 后打不进搜索框 |
| D14 | 页面侧仍在 `focus`/`visibilitychange` 时补一次 input.focus | 新建策略失效时（例如浏览器策略变化）还能靠 Esc 把焦点交回页面时自动落位 |
| D15 | 源类型支持 `json`（默认）与 `html`；HTML 源只允许用户自建，不预置 | 自用场景下抓网页是合法且省钱的补充，但它依赖对方页面结构、随时失效，不能当作内置源的稳定性基线 |
| D16 | `origin` 支持字符串或数组，权限按每个落点分别检查与申请 | 实测 `www.bing.com` 会 302 到 `cn.bing.com`；只授权前者时 fetch 直接失败，且错误信息完全看不出原因 |
| D17 | 缺省 `enabled` 视为启用（`enabled !== false`） | 手写配置通常不写这个字段。此前设置页按 `!== false` 显示为启用、搜索却按真值过滤，导致「界面显示启用、实际不参与搜索」 |

## 6. 风险

1. **外部结果质量不可控**：如果结果读起来不如直接用 Kagi/Perplexity，项目应停在 M1。这是预设止损点。
2. **声明式配置的维护债**：搜索源会因字段改名、限流策略变化而失效；开放给他人自定义等于接手兼容性包袱。
3. **软接管的闪烁**：新标签页会先闪一下 Chrome 默认页。若不可接受，只能改回硬接管（装之前定死）。
4. **多源交错仍是伪排序**：名次交错只保证"不伪造分数"，不等于"好的排序"。
